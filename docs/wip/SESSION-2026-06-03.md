## Decisions

All decisions are recorded in `docs/adr/0005-annotation-highlight-layer.md` (the addenda for each
cycle are inline). Summary of the non-obvious ones:

**Verse markup redesign (5b).** The ADR-0004 verse `<button>` blocked native text selection.
Dropped in favor of: verse = selectable non-interactive `div`/`span` (`data-verse={n}`); verse
text = `<span data-text-segment>` runs (only these count in offset math); verse number = a
focusable `<button data-testid="verse-{n}-new-entry">` with hover/focus affordance. Note markers
and the number button are NOT `data-text-segment`, making the browser offset coordinate space
identical to the backend's `char_offset`. Mobile tap-target sizing was deferred from 5b to 5c-4.

**Selection→offset seam (5b).** `rangeToVerseSelection` is pure and takes a `Range`-like object —
testable with jsdom-constructed Ranges. `resolveSelection()` is the only function touching
`window.getSelection()` and is not unit-tested (manual/E2E only). Component tests inject
`resolveSelectionFn` prop to drive the popover without real browser selection.

**Multi-verse end-offset (5c-1).** `char_end` is measured in `verse_end`'s own coordinate space
(not relative to `verse_start`). This matches the backend schema and is non-obvious. The test has
a discriminating assertion that would catch a bug measuring in `verse_start`'s space.

**Panel over popover for existing highlights (5c-3).** The small Remove popover was retired; all
existing-highlight interaction goes through `AnnotationPanel`. The resolution change (click span
→ `onOpenAnnotations(ids)` instead of `onRemoveHighlight(id)`) migrated three ChapterContent
tests by design (documented in ADR with before/after shapes).

**CSS-only responsive shell, single render (5c-4).** `ReaderPanelShell` renders its children once
and uses Tailwind `lg:` variants to flip between bottom-sheet and docked column. Deliberate
avoidance of a JS `useMediaQuery` hook for layout (which would cause duplicate `id`/`testid` in a
desktop+mobile copy approach). `useMediaQuery` IS used, but only for the focus-trap decision in
5c-6 (modal semantics apply only to the bottom-sheet, not the docked column).

**Refetch-not-optimistic mutations (throughout).** All annotation mutations trigger a server
refetch on success rather than optimistic updates. Simpler; acceptable given annotation operations
are low-frequency. Error feedback (5c-6) relies on this: a failure leaves the UI coherent with
the last successful server state, so there is no half-applied limbo to roll back.

**Error feedback pattern (5c-6).** An inline dismissible `role="alert"` banner in ReaderPage, not
a toast library. Consistent with existing `ChapterError`/`EntryForm` inline alert pattern. No new
dependency added.

## Watch out for

**`noUncheckedIndexedAccess` is on.** TypeScript strict mode includes this flag
(`frontend/tsconfig.json`). Array indexing returns `T | undefined`. This bites frequently when
adapting examples from the internet or porting code. Always narrow before use.

**`npm ci` must be run first.** Frontend deps are frequently uninstalled between sessions
(noted in memory file). Always `cd frontend && npm ci` before running typecheck/lint/test.

**The 5 verse-button tests were migrated in 5b.** Five named tests in `ReaderPage.test.tsx`,
`ChapterPane.test.tsx`, and `ChapterContent.notes.test.tsx` were rewritten when the verse
`<button>` was replaced by the `data-verse` + verse-number-button markup. They no longer test
`tagName === "BUTTON"` on verse elements. If someone adds a new test assuming a verse is a
`<button>`, it will fail — this is correct behavior, not a test bug.

**The Remove popover no longer exists.** Three ChapterContent tests that used to assert
`onRemoveHighlight` were migrated in 5c-3 to assert `onOpenAnnotations`. Any grep for
`onRemoveHighlight` or `SelectionPopover` with a Remove action is stale. The popover now has only
color swatches + a Cancel button (create flow only).

**`char_end` is in `verse_end`'s coordinate space, not `verse_start`'s.** For multi-verse
annotations, `char_start` indexes into `verse_start`'s text and `char_end` indexes into
`verse_end`'s text independently. This is the stored contract (backend schema) and the
`rangeToVerseSelection` output. Code that treats them as a single continuous offset range is wrong.

**Backend test suite is slow for real-PDF tests.** Default pytest runs in ~23s. The slow marker
(`-m slow`) covers real-PDF parser tests (~10 min). Always background the full run: the default
suite is the fast gate.
